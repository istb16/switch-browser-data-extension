# Grill: 設定画面へのバージョン番号表示
Date: 2026-07-24

## Intent
サポート対応時に「ユーザーがどのバージョンを使っているか」を確認できるようにするため、設定画面 (options.html) にバージョン番号を表示する。

## Constraints
- ビルドパイプラインは存在しない（`deploy/build.*` は zip 化のみで、タイムスタンプやバージョンの注入は行わない）
- 依存ライブラリなし・TypeScript不使用というプロジェクト方針を維持する

## Key decisions
- Decision: ビルド日時は表示しない、バージョン番号のみ表示する。Reason: ビルド日時を記録する仕組みが現状存在せず、コミット時刻を代用する案・パッケージング時刻を使う案のどちらも過剰。目的（サポート時のバージョン確認）にはバージョン番号だけで十分。
- Decision: バージョン番号は `chrome.runtime.getManifest().version` を実行時に参照して表示する。Reason: 別ファイルで二重管理せず、常に実際のバージョンと一致させるため。CLAUDE.md に追加済みの「コミット時に manifest.json のバージョンを加算する」ルールとも整合する。
- Decision: 表示場所は options.html の最下部、`<section>` 見出し付きではなく `<footer>` 的な1行の目立たない表示にする。Reason: バージョン情報は操作項目ではなく参照情報であり、他の操作セクションと同列に扱うと目的が伝わりにくい。
- Decision: 表示は options.html（設定画面）のみとし、popup.html には追加しない。Reason: ポップアップはドメインごとのスナップショット操作に特化した最小限のUIであり、サポート用の補足情報を混ぜると煩雑になる。設定画面は「設定ボタン」から明示的に開く画面なので、そこに載せるのが適切。
- Decision: 表示文言は既存の `lib/i18n.js` の多言語対応パターンに合わせる（例: `saved_at: '保存日時: {date}'` と同様に `バージョン: {version}` / `Version: {version}`）。Reason: 既存の options.html はすべての文言が `data-i18n` 経由で ja/en 対応しており、一貫性のため。

## Out of scope
- ビルド日時の表示（仕組みが存在しないため）
- popup.html へのバージョン表示追加
